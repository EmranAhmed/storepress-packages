# Plugin example

A StorePress plugin has three parts: the plugin function (`plugin.js`), the plugin manager (`index.js`) and the start script (`script.js`).
<br />See the [package README](https://github.com/EmranAhmed/storepress-packages/blob/main/packages/utils/README.md#building-a-plugin) for the full rules.

## Install

```shell
npm i @storepress/utils --save
```

## 1. The plugin `plugin.js`

A plain function that sets up one element and returns its public API. Don't use `this`: keep state in local variables.

```js
'use strict';
/**
 * External dependencies
 */
import { deepMerge, getOptionsFromAttribute } from '@storepress/utils';

// Default settings for every instance.
const DEFAULTS = {
	size: 20,
};

// Values the user must not override from options or attributes.
const PRIVATE = {};

const ATTRIBUTE = 'slider-settings'; // data-slider-settings

const CSS_CLASSES = [ 'example-input-class' ];

function Plugin( element, options ) {
	// Later sources win: DEFAULTS < manager options < data-* attributes < PRIVATE.
	const settings = deepMerge(
		DEFAULTS,
		options,
		getOptionsFromAttribute( element, ATTRIBUTE ),
		PRIVATE
	);

	// One signal removes every listener this instance adds.
	const controller = new AbortController();

	const $inputs = element.querySelectorAll( 'input' );

	const handleInput = ( event ) => {
		window.console.log( event.target.value, settings.size );
	};

	const addClasses = () => {
		$inputs.forEach( ( $input ) => $input.classList.add( ...CSS_CLASSES ) );
	};

	const removeClasses = () => {
		$inputs.forEach( ( $input ) => $input.classList.remove( ...CSS_CLASSES ) );
	};

	const addEvents = () => {
		const { signal } = controller;
		$inputs.forEach( ( $input ) => {
			$input.addEventListener( 'input', handleInput, { signal } );
		} );
	};

	const removeEvents = () => {
		controller.abort();
	};

	const handleNext = () => {
		// Public method other scripts can call.
	};

	/**
	 * Called by the plugin manager on destroy, so the name must stay `reset`.
	 */
	const reset = () => {
		removeEvents();
		removeClasses();
	};

	addClasses();
	addEvents();

	// Do not use `element` or `destroy` as keys: the manager sets them.
	return { reset, handleNext, settings };
}

export { Plugin };
```

## 2. The plugin manager `index.js`

```js
'use strict';
/**
 * External dependencies
 */
import { createStorePressPlugin } from '@storepress/utils';

/**
 * Internal dependencies
 */
import { Plugin } from './plugin';

const Slider = createStorePressPlugin( {
	selector: '[data-slider-settings]',
	plugin: Plugin,
	namespace: 'slider',
	options: { size: 50 }, // Site-wide overrides; plugin defaults live in DEFAULTS.
} );

// Adds the init, destroy and reload event listeners.
Slider.setup();

export default Slider;
```

## 3. The start script `script.js`

```js
'use strict';
/**
 * Internal dependencies
 */
import Slider from './index';

domReady(function () {
    Slider.init()
})
```

## Example HTML

Settings can come from a JSON attribute (relaxed single-quote notation works too), from one attribute per option, or both.

```html
<div id="container">
	<div class="slider-wrapper" data-slider-settings="{'size': 40}">
		<a>1</a>
		<form>
			<input type="text" placeholder="Location X" />
		</form>
	</div>

	<div class="slider-wrapper" data-slider-settings data-slider-settings--size="30">
		<a>2</a>
		<form>
			<input type="text" placeholder="Location Y" />
		</form>
	</div>
</div>
```

## Controlling the plugin from other scripts

### With imports

```js
'use strict';
/**
 * External dependencies
 */
import { getPluginInstance, getStorePressPlugin } from '@storepress/utils';

// Instances for specific elements.
const instances = getPluginInstance( '.slider-wrapper', 'slider' );

// The manager registered by createStorePressPlugin().
const Slider = getStorePressPlugin( 'slider' );

// All instances for the manager's selector.
Slider.get().forEach( ( instance ) => {
	instance.handleNext(); // Call what the plugin returned.
} );

Slider.init(); // Create instances for new elements; existing ones are skipped.
Slider.reload( '#hero', { size: 10 } ); // Rebuild with new settings.
Slider.destroy(); // Call reset() on every instance.
```

### Without a bundler

The manager is stored on `window.StorePress.$Plugins`. The key is the namespace in UpperCamelCase, so `slider` becomes `Slider` and `storepress-slider` becomes `StorepressSlider`.

```js
'use strict';
const Slider = window.StorePress?.$Plugins?.Slider?.Plugin;

Slider?.get().forEach( ( instance ) => instance.handleNext() );
```

Any script can also start, stop or reload the plugin by dispatching the manager's events on `document`, without importing anything:

```js
document.dispatchEvent(
	new CustomEvent( 'storepress:slider:init', {
		detail: { element: '.slider-wrapper', settings: { size: 30 } },
	} )
);
```

## Plugin with an event manager

The plugin above uses one `AbortController` per instance, which is enough for most plugins. When a plugin needs namespaced custom events, listener inspection or automatic removal, build it on `createEventManager` instead.

### Rules

1. **Create one event manager per plugin, outside the plugin function.** All instances share it.
2. **Never call `events.removeAll()` in `reset()`.** Managers with the same namespace share one store, so `removeAll()` removes every instance's listeners. Remove only what this instance added, with `events.remove( target, type, handler )`.
3. **Don't reuse the plugin manager's namespace.** This page's manager uses `slider`, so the plugin's events use `slider-ui`. Sharing `slider` would let a `removeAll()` delete the manager's `init`, `destroy` and `reload` listeners.
4. **Announce events with `triggerEvent()`.** `events.trigger()` only reaches handlers this event manager added to that element, so outside listeners never see it.
5. **Avoid custom names that match native events.** `change`, `select` and `input` are attached as native events. Use `slide-change`, not `change`.

### Event manager plugin `plugin.js`

```js
'use strict';
/**
 * External dependencies
 */
import {
	createEventManager,
	deepMerge,
	getOptionsFromAttribute,
	triggerEvent,
} from '@storepress/utils';

const DEFAULTS = {
	loop: true,
};

const ATTRIBUTE = 'slider-settings'; // data-slider-settings

// Must differ from the plugin manager's namespace ('slider').
const EVENT_NAMESPACE = 'slider-ui';

// One event manager for all instances. Each instance removes only its own handlers.
const events = createEventManager( EVENT_NAMESPACE );

function Plugin( element, options ) {
	const settings = deepMerge(
		DEFAULTS,
		options,
		getOptionsFromAttribute( element, ATTRIBUTE )
	);

	const $slides = element.querySelectorAll( '.slide' );
	const $prev = element.querySelector( '.prev' );
	const $next = element.querySelector( '.next' );

	let index = 0;

	// Track what this instance adds, so reset() removes only that.
	const added = [];

	const on = ( target, type, handler, eventOptions ) => {
		events.add( target, type, handler, eventOptions );
		added.push( [ target, type, handler ] );
	};

	const removeEvents = () => {
		added.splice( 0 ).forEach( ( [ target, type, handler ] ) =>
			events.remove( target, type, handler )
		);
	};

	const goTo = ( newIndex ) => {
		const last = $slides.length - 1;
		const wrapped = newIndex > last ? 0 : newIndex < 0 ? last : newIndex;
		index = settings.loop ? wrapped : Math.min( Math.max( newIndex, 0 ), last );

		// Tell other scripts. Listen with:
		// element.addEventListener( 'storepress:slider-ui:slide-change', ... )
		triggerEvent(
			element,
			`storepress:${ EVENT_NAMESPACE }:slide-change`,
			{ index },
			{ bubbles: true }
		);
	};

	const next = () => goTo( index + 1 );
	const prev = () => goTo( index - 1 );

	/**
	 * Called by the plugin manager on destroy, so the name must stay `reset`.
	 */
	const reset = () => {
		removeEvents();
	};

	const handleKeydown = ( event ) => {
		// The markup was replaced without destroy(): clean up and stop.
		if ( ! element.isConnected ) {
			reset();
			return;
		}
		if ( ! element.contains( document.activeElement ) ) {
			return;
		}
		if ( event.key === 'ArrowRight' ) {
			next();
		}
		if ( event.key === 'ArrowLeft' ) {
			prev();
		}
	};

	const addEvents = () => {
		on( $next, 'click', next );
		on( $prev, 'click', prev );
		// Shared target: safe, because reset() removes this exact handler.
		on( document, 'keydown', handleKeydown );
	};

	addEvents();

	// Do not use `element` or `destroy` as keys: the manager sets them.
	return { reset, next, prev, goTo, settings };
}

export { Plugin };
```

The manager (`index.js`) and start script (`script.js`) stay the same.

### Listening from other scripts

```js
'use strict';
document.addEventListener( 'storepress:slider-ui:slide-change', ( event ) => {
	// event.target is the slider element.
	highlightThumbnail( event.target, event.detail.index );
} );
```

## Updating markup with AJAX

Instances belong to elements. When AJAX changes the markup, tell the plugin manager what happened. The same steps work for both plugin versions.

### Markup is replaced (filters, pagination, quick view)

Destroy the instances inside the markup you are about to replace, replace it, then init the new markup. Destroying first runs each instance's `reset()`, so listeners on `document` and `window` are removed too.

```js
'use strict';
/**
 * Internal dependencies
 */
import Slider from './index';

const RESULTS = '.products';
const SLIDERS = `${ RESULTS } [data-slider-settings]`;

async function loadProducts( url ) {
	const response = await fetch( url );
	const $page = new DOMParser().parseFromString( await response.text(), 'text/html' );

	// 1. Reset and forget the instances in the old markup.
	Slider.destroy( SLIDERS );

	// 2. Replace the markup.
	document.querySelector( RESULTS ).replaceWith( $page.querySelector( RESULTS ) );

	// 3. Create instances for the new markup.
	Slider.init( SLIDERS );
}

document.querySelector( '.product-filters' ).addEventListener( 'change', ( event ) => {
	const url = new URL( window.location.href );
	url.searchParams.set( event.target.name, event.target.value );
	loadProducts( url );
} );
```

Destroy after the response arrives, not before the request, so the old sliders keep working while the page loads.

### Markup is added (load more, infinite scroll)

Only call `init()`. Elements that already have an instance are skipped, so existing sliders keep their state.

```js
'use strict';
document.querySelector( '.load-more' ).addEventListener( 'click', async ( event ) => {
	const response = await fetch( event.currentTarget.dataset.nextPage );
	document.querySelector( '.products' ).insertAdjacentHTML( 'beforeend', await response.text() );

	Slider.init();
} );
```

### Markup is replaced by code you don't control (WooCommerce fragments)

WooCommerce replaces cart fragments and the cart table without warning, so you can't call `destroy()` first. Call `init()` afterwards for the new markup:

```js
'use strict';
jQuery( document.body ).on( 'wc_fragments_refreshed wc_fragments_loaded updated_wc_div', () => {
	Slider.init();
} );
```

The old instances are cleaned up without `reset()`:

- **Listeners on the removed elements:** the event manager removes them automatically (`autoRemove`). With the `AbortController` version, they are garbage collected with the elements.
- **The instance itself:** the instance store is a `WeakMap`, so it is released with its element.
- **Listeners on `document` or `window`:** these are not removed automatically. Check `element.isConnected` in those handlers and call `reset()` when it is `false`, as `handleKeydown` does above.
